# Пересоздание основной инфраструктуры

Цикл проверен 8 ноября 2026 года: удалены и созданы 13 ресурсов main,
восстановлены пять образов с пятью исходными тегами, повторный Terraform plan
вернул `No changes`. Затем заново установлены Kubernetes и сервисы.
[Результаты проверки](verification-2026-11-08.md).

Bootstrap, бакет state и сервисные аккаунты сохраняются. Main включает три ВМ
с boot-дисками, два статических IP, Registry, сеть, три подсети и security groups.
Удаление ВМ уничтожает local PV: история Prometheus и локальные изменения Grafana
не переносятся. Дашборды из Git устанавливаются заново.

## Подготовка

Команды выполняются из корня infra на Mac с установленными Terraform, yc,
Python 3.11+ и crane (`brew install crane`). Docker daemon не требуется.
Используются существующие ключ Terraform, bootstrap state, tfvars и S3-доступы
из [окружения main](operations.md#окружение-main).

До цикла отключите автозапуск через bootstrap по [инструкции](operations.md).
Дождитесь завершения Actions в обоих репозиториях. До окончания цикла
не делайте push, не запускайте Actions или другой Terraform. Проверки скрипта
не блокируют новый запуск GitHub Actions; распределённой блокировки state нет.

Сохранение state/ключей, образов и проверка их загрузки:

```bash
python3 scripts/prepare-recreate.py
python3 scripts/backup-registry.py --infra "$PWD"
python3 scripts/registry-recovery.py --infra "$PWD" --test-upload
python3 scripts/recreate-main.py --infra "$PWD" --plan
```

Первые два скрипта только читают облачные ресурсы и сохраняют приватные копии.
Test upload загружает те же manifest по digest в исходный реестр и сверяет их,
не удаляет образы и не переносит теги. Последняя команда проверяет свежую копию,
успешный upload test за последние 24 часа, выключенный автозапуск, отсутствие
активных Actions и destroy-план: только 13 ожидаемых ресурсов main в этом каталоге.

Все state, планы, ключи, OCI-копии и журналы остаются в `.secrets` с закрытыми
правами. Резервная копия state не является копией дисков ВМ. Для очередного
цикла нужна новая копия текущего Registry: после нового релиза старый набор
образов и тегов уже не соответствует реестру.

## Выполнение

После разбора вывода `--plan` следующая команда удаляет работающий стенд:

```bash
python3 scripts/recreate-main.py --infra "$PWD" --execute
```

Скрипт принимает неиспользованный план моложе четырёх часов, повторно сверяет
конфигурацию, state, GitHub main SHA и конкретные ID/digest/теги образов. Далее:

1. Удаляет только образы из проверенной копии.
2. Применяет сохранённый destroy-план и проверяет пустой main state.
3. Создаёт план на те же 13 адресов ресурсов, допускает только create, применяет его.
4. Проверяет `No changes` и восстанавливает образы с проверкой manifest и тегов.

Очистка Registry автоматизирована отдельным скриптом. Образы опубликованы CI
и не управляются Terraform; обычный destroy непустого реестра требует этой
подготовки. Bootstrap не получает apply/destroy. Скрипт ограничен этим проектом:
при изменении состава main сначала пересматриваются его проверки.

Сообщение `main_and_images_recreated` подтверждает main и образы.
Оно ещё не означает установленный Kubernetes или доступное приложение.

## Если выполнение остановилось

Не повторяйте `--execute` с уже начатым отчётом. Сначала проверьте записанную фазу,
приватный журнал и фактический Terraform state. Не загружайте старый state
поверх частично удалённых ресурсов. Облачная операция после таймаута могла
продолжиться; повторять её без проверки нельзя.

Если восстановление только образов нужно продолжить в текущем реестре,
`registry-recovery.py --restore` проверяет его содержимое перед загрузкой.
`--verify-only` проверяет уже загруженные образы без push/tag/delete.

Для случая, когда исходный цикл дошёл до `restoring_images`, образы уже загружены,
а конфигурация и GitHub main SHA с тех пор не менялись:

```bash
python3 scripts/recreate-main.py --infra "$PWD" --finish-restoration
```

Этот режим проверяет новые ID всех 13 ресурсов, существующие manifest/теги
и `No changes`, затем завершает исходный отчёт. Он не выполняет apply/destroy.
Дополнительная запись в `tags`, равная digest самого образа, исключается из
сравнения обычных тегов; чужой digest или посторонний тег вызывают ошибку.

## Установка сервисов после цикла

1. Обновить inventory; сверить новые SSH host keys через serial console YC.
   Проверку host keys не отключать.
2. Выполнить Ansible site.yml и install-kubeconfig.py.
3. Создать imagePullSecret, установить Traefik и приложение из восстановленного тега.
4. Установить мониторинг и проверить Grafana. Local PV будут пустыми.
5. В Actions приложения заменить `YC_REGISTRY_ID`, `APP_URL` и созданный заново
   ограниченный `KUBE_CONFIG`; старые сертификаты/токен к новому кластеру не подходят.
6. Проверить три Ready-узла, две реплики, HTTP, Grafana и все scrape targets.
7. Включить ограниченное окно автозапуска и обновить ссылки для сдачи.

Команды установки: [deploy.md](deploy.md). Пароль Grafana передаётся отдельно.
